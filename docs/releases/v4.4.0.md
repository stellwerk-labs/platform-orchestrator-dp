# Data Plane 4.4.0

PostgreSQL transport security is configurable through `DATABASE_SSLMODE`. The default remains `disable`; set `require` to enforce encryption without plaintext fallback, or `verify-full` with `PGSSLROOTCERT` to verify the server certificate and hostname. The existing driver handles certificate settings and rejects invalid modes during database initialization.

Connection-string values are quoted correctly, including spaces, quotes and backslashes in credentials or database names. The server and its migrations use the same effective connection string. These startup settings require a restart.

Existing installations retain their database connection behavior until the operator opts into TLS.

Observation jobs now default to `INFO` logging so a compatible Runner can emit
its optional Infracost cost-estimation summary. The safe observation executor continues to
keep private plan output out of logs. These jobs retain their existing absence
of encrypted-log capture; estimates appear in runtime logs. Explicit operator
log-level overrides continue to apply.

Cost estimation defaults disabled and is managed through installation Administration.
Administrators can enable estimates and save, replace or clear a write-only Infracost API key.
The key is encrypted with Vault Transit in installation storage; ordinary settings reads and audit records expose only presence and change flags.
New executions freeze the enabled decision; each dispatch resolves the current credential, including retries.
Unavailable credentials skip estimates without blocking deployment.

Dispatch uses the existing deployment-token trust boundary: Job and ECS task-definition administrators, remote JetStream readers and diode frame readers can access the key copied into execution environment.
Rotation affects future dispatches, but does not revoke a key already copied into a queued command.

## Managed deployment logs

API callers can request `managed_logs: true` without an explicit recipient. The
Data Plane creates a fresh age key per deployment, stores only its Vault
Transit-wrapped private identity, and passes the public recipient to the Runner.
Queue, Draft tests and rollback preserve the requested custody mode. Omitting
both fields keeps existing API behavior, with no captured logs.

`GET .../actions/get-logs?decrypt=true` returns authorized managed plaintext.
All plaintext reads, including explicit `DecryptKey` requests, require the
dedicated `deployment_logs_read` permission on the exact Environment or its
organization. Existing ciphertext retrieval is unchanged. Logs without retained
managed identities return a conflict instead of ciphertext. Responses are bounded
and successful log responses prohibit caching.

Migration `43` adds deployment log material. Keep its database rows and historical
Vault Transit key versions in backups. Downgrading with its Down migration drops
managed identities and loses automatic access unless restored. Deploy IAM with
the new permission before enabling managed reads; grant custom roles explicitly.
