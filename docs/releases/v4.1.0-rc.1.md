# Data Plane v4.1.0-rc.1

This prerelease is for evaluation with the matching Control Plane, IAM,
Runner, clients, Console and gateway routes. It is a candidate, not a
completed coordinated release. Use the final qualified compatible chart set
when it becomes available.

## Immutable Draft test execution

A caller explicitly selects immutable Draft test snapshot UUIDs through the
module-test deployment route. The normal planner, queue, admission, encrypted
artifacts and Runner execute those exact snapshots. Editing a Draft leaves
earlier A/B captures, queued work and retained deployments unchanged. Pins
remain authoritative. Ordinary published deployments retain their existing
API route and catalogue transport; an unsupported server must not substitute
a published Default for a Draft test.

The Environment destroy worker reads retained Draft material through the
authenticated runtime catalogue client. It reconstructs the exact stored
source without rereading a moving Draft head or granting new authoring
authority. New test and catalogue routes require the matching Control Plane
and gateway configuration. Existing published HTTP operations remain
available.

## Go SDK and release controls

The separately published Data Plane shared Go SDK uses
github.com/stellwerk-labs/platform-orchestrator-dp/shared/v3. Its generated
client interfaces gain methods; custom Go implementations must migrate.
The Go major-version path does not itself mean that existing HTTP routes were
removed. The application image tag does not publish the nested SDK module.

The release-content path now refuses a declared SDK without an exact Git source
commit, module checksum and byte-verified licence provenance. This is a
publication control correction, not a deployment behavior change.

## Upgrade and recovery

Storage migrations 36 and 37 retain exact Resource Type interface and
executable Draft provenance. Upgrade this compatible Data Plane before
enabling the new Control Plane workflows, then update Console and clients.
Back up the databases, encryption material, configuration and outstanding
deployments first. Older CP/DP binaries refuse the new schemas. Do not
downgrade to old binaries or run destructive Down migrations as routine
recovery; use schema-compatible images or a forward fix. Database restore is
a separate recovery operation.

Isolated source-built native CP/IAM/DP/Runner execution, CLI and
Terraform/OpenTofu flows, Console, normal teardown and seeded cross-service
upgrade/restart have been exercised. Final packaged image upgrade/recovery,
plugin compatibility and the complete public chart set remain qualification
gates. This candidate note does not claim those checks have passed.
