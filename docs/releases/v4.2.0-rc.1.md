# DP v4.2.0-rc.1

Read-only Environment observations and persistent Runner capacity.

Release candidate; qualify this exact coordinated artifact set before stable
promotion.

## Changes

- Add optional observation/recovery APIs and use public CP shared/v3 v3.1.0,
  DP shared/v3 v3.1.0 and IAM shared v1.3.0 without local replacements. Existing mandatory
  shared interfaces remain compatible.
- Admit a read-only observation only when its Environment has neither running nor
  queued work and the configured Runner has capacity. Busy observations skip;
  normal deployment queues remain authoritative.
- Capture the latest successful ordinary deployment or rollback, including normal
  plugin-dispatched deployments. A later failed or uncertain mutation blocks an
  older baseline. No current catalogue default substitutes for captured inputs.
- Execute a normal refreshed plan without apply or state writes. Retained results
  contain bounded opaque IDs, resource types, actions and counts, not raw plans,
  addresses, attributes, outputs or provider diagnostics. Missing/invalid results
  remain unavailable/error, never clean.
- Persist max_parallel_jobs reservations across all Runner job paths. Omission
  preserves legacy unlimited capacity; configured lower limits drain existing
  work. Unknown stop ownership is retained until an authoritative outcome.
- Reconcile ambiguous observation and ordinary corrective-deployment requests by
  exact immutable identity/receipt or atomic not-started seal, never a fresh retry
  that can duplicate an accepted effect.

## Upgrade and recovery

The coordinated DP upgrade advances database schema37 to39 through migrations38
and39. Back up affected databases, roles/ACLs/sequences and deployment state, stop
incompatible writers, and use the qualified IAM/CP/DP/Runner artifact set.

Observation execution requires a positive Runner capacity limit and an explicit
environment-observation/v1 declaration matching its actual executable. An older
Runner remains plan-only safe but provides no valid observation result, which is
unavailable rather than clean. Shared capacity covers ordinary and observed work.

Retained immutable inline source can qualify without an artifact digest. A
digest-free external Git source must pin a full lowercase commit in its executable
git::https:// or git::ssh:// selector. Supplied digests must match retained and
retrieved material; a descriptive revision label alone does not freeze a mutable
URL. Existing lifecycle, state-head and ordinary admission checks remain.

Use verified restore/forward recovery, not an assumed binary or Helm rollback
after new receipt/journal writes. Clock expiry does not prove an accepted Runner
stopped and never releases its authority by itself. Ordinary deployment/rollback/
destroy behavior remains intact; plugin absence creates no observation schedule.

## Release security scope

The coordinated release records explicit, release-scoped acceptance of known
residual advisories in ORAS1.3.6, Cosign3.1.4 and the Runner's official bundled
OpenTofu1.13.2 after the upstream recheck. This acceptance applies only to this
release and those vendor artifacts. Component source and executable checks remain
strict; it does not suppress findings in this component or replace the final
artifact/provenance checks.
