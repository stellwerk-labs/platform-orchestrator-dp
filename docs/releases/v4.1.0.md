# Data Plane v4.1.0

## Immutable Draft test execution

A caller explicitly selects immutable Draft test snapshot UUIDs for an
Environment through the module-test deployment route. The normal planner, queue,
admission checks, encrypted artifacts, and Runner execute those exact snapshots.
Editing a Draft leaves earlier captures, queued work, and retained deployments
unchanged. Pins remain authoritative. Ordinary published deployments keep their
existing API route and catalogue transport; an unsupported server must not
substitute a published Default for a Draft test. Draft publication is a separate
Control Plane action that closes the exact revision as Proposed; it does not
make it Default or deploy it.

The Environment destroy worker reads retained Draft material through the
authenticated runtime catalogue client. It reconstructs the exact stored source
without rereading a changing Draft head or granting authoring authority.

## Compatibility

The Data Plane shared Go SDK uses the separate
`github.com/stellwerk-labs/platform-orchestrator-dp/shared/v3` module path. This
Go major version can require source changes to imports and generated-client
interface implementations; it does not remove existing HTTP operations. Existing
Module Versions retain their Resource Type interface binding, and older callers
that omit an interface version continue to select version 1. New test and
catalogue routes require matching Control Plane and gateway support. When a
requested route is unavailable, clients must report an error rather than
substitute a published Default.

## Upgrade and recovery

Data Plane migrations 36 and 37 retain exact Resource Type interface selections
and executable Draft provenance. Upgrade the compatible Data Plane before
enabling the new Control Plane workflows, then update the Console and clients.
Older Control Plane or Data Plane binaries refuse the new schemas. Do not use
old binaries or destructive Down migrations as routine recovery; use
schema-compatible images or a forward fix. A database restore is a separate
recovery operation. Back up databases, encryption material, configuration, and
outstanding deployments first.
