# Data Plane 4.2.2

Removing a resource can fail when the current Module catalogue no longer includes
its original version. This affects migrated legacy graphs and managed versions
when a Default, Pin or matching Rule changes. Previously the missing definition
could produce HTTP 500 before a Deployment or plan was created.

Compilation now resolves exact historical metadata for removed nodes after
selecting the new graph. It preserves the original provider aliases and hashes,
without changing the current Module selection or Environment Pins. Rollback,
destroy and Runner inline-source reconstruction use the same authenticated
material-only execution catalogue. This retrieves retained material; it does not
authorize a new deployment or migrate Terraform state to another resource.

Missing historical versions or providers stop compilation with HTTP 409 and a
recovery message. Invalid graph nodes return HTTP 400 instead of an internal
configuration error. Historical material must remain available for cleanup.
Deleting a provider's own dependencies still requires a valid dependency graph.

Use the compatible Core set: CP 3.3.0, IAM 2.6.0 and Runner 3.2.0. CP 3.1.1 does
not expose the required authenticated material-only API, so this is not a
DP-only upgrade for installations on that version. Configure the normal Core
admission gateway and service identity. Existing central admission checks remain
in force. Relative to DP 4.2.1, this patch adds no API, SDK, database migration
or Runner protocol. Upgrades from older versions still apply the intervening
migrations.
The historical `TfVarPlaceholder` Gob compatibility reader from DP 4.2.1 is
retained.

The server also updates existing Echo and compression dependencies to their
security fixes. Its vulnerability gate verifies the exact upstream-fixed Echo
4.16.3 module and the full hashes of two stale Go vulnerability records. Other
called vulnerabilities and changed records still fail the gate, and the complete
scanner output is retained.

A separate final integration phase exercises real IAM admission, plan-only state
preservation, failed cleanup and retry, rollback, and destroy for both opaque
legacy versions and managed versions. Run `make -C integration-tests
test-historical-removal` after the normal integration suite. It leaves admission
enabled until the normal cleanup removes the disposable proxy.
